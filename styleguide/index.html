The parts Excellent is built from, for anything you build

Design tokens as CSS variables, and plain components on top of them: buttons, badges, fields, cards, tables, the app shell. Light and dark, comfortable and compact. No framework, no build step and no dependencies, so a single-file viewer a CLI serves looks the same as a React app.

It's the kit behind Excellent's admin and app, and behind screen-map, selfdocs, pressroom and the rest. MIT licensed.

npm i @excellent-so/kit Code

The rules

Seven things every part keeps, so anything built from it reads as one family.

  1. Ink on white. Light by default, whatever the OS says. Dark is a choice the reader makes, and the page remembers it.
  2. Two colours mean something. Amber is for Verified, and red is for Returned or failed. Nothing else is coloured: every other state is an outline.
  3. A state never rests on colour alone. Every verdict and status badge carries a glyph: a stepped check, a way back, a cross, an open square.
  4. Controls have 4px corners and are 44px tall. Compact density draws 36px on a mouse or trackpad; touch keeps 44px.
  5. Surfaces are flat. A 1px hairline and 8px corners. Shadows are for things that float over the page.
  6. Tables, not paragraphs. Data goes in a table with numbers right-aligned in tabular figures; on a phone each row stacks.
  7. One focus ring. Everything a keyboard can reach shows the same 2px ring, and small text stays at 12px or larger.

Using it

In a page
Link the files, put ex-page on the body, and use the classes.
<link rel="stylesheet" href="@excellent-so/kit/fonts.css">
<link rel="stylesheet" href="@excellent-so/kit/tokens.css">
<link rel="stylesheet" href="@excellent-so/kit/kit.css">
<script src="@excellent-so/kit/kit.js" defer></script>

<button class="ex-btn">Run the check</button>
<span class="ex-badge ex-badge--verified">Verified</span>
In a single-file viewer
Mark a spot in its <style> and let the command write the kit there. --check fails CI when it's out of date.
<style>
/* excellent-kit:begin */
/* excellent-kit:end */
</style>

npx @excellent-so/kit sync viewer/index.html
npx @excellent-so/kit sync viewer/index.html --check
With Tailwind or a native app
tokens.json has every value, light, dark and compact, to map into a theme.
import tokens from '@excellent-so/kit/tokens.json'
// tokens.light['--color-strong']  → "#0E0E0E"
// tokens.dark['--color-strong']   → "#F0F0F2"

Space and corners

One unit of 8px; one line of body text is 24px. Inside a part, multiples of the unit; between blocks, the scale.

Glyphs

Drawn on a 2px grid, as masks in the current colour. One arrow for every link that goes somewhere.

--glyph-arrow --glyph-arrow-back --glyph-check --glyph-cross open square

Marks

Each tool on the kit has its own mark, never Excellent's. Drawn on a 16-unit grid in the current colour: filled shapes and 2-unit lines, ink only, never amber. It sits left of the name at 16px (.ex-mark), and the same drawing is the favicon and the head of the README.

Buttons

One solid button per view, for the thing you came to do. The rest are outlines or ghosts.

The dither

Excellent's amber texture: dots on the page's grid, as a band or a fill. Decoration only, never behind words.
